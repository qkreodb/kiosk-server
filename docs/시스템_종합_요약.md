# 시스템 종합 요약 (docs 통합본)

> `docs/` 의 개별 작업 문서들을 종합한 **시스템별 개요 + 파이프라인** 단일 요약.
> 상세 이력·트러블슈팅은 각 원본 문서 참고(맨 아래 색인).

## 1. 전체 아키텍처

산업 안전보건 키오스크(1080×1920 터치)의 백엔드 = **Kiosk Main Server (FastAPI, PORT 8080)**.
외부 구성요소와의 관계:

```
[IP 카메라 ×2] --RTSP--> ┌─────────────────────────────┐
                         │  Kiosk Main Server (8080)    │ --HTTP--> [브라우저 kiosk.html]
[MySQL dasol] <--PyMySQL--│  · Shared DB 조회/카운팅     │            (백엔드가 직접 서빙)
 (Jetson)                │  · RTSP→MJPEG 중계           │
                         │  · VLM 호출 + 후처리          │--HID--> [경광등 ST80EL-USB]
[VLM Server (8000)] <----│  · TTS 합성/재생(스피커)      │
 Jetson Thor, Qwen2.5-VL └─────────────────────────────┘
[Hardware Server (8081)]  … 센서(MQTT)→DB 적재, 프레임 기록(Shared Dir) — 별도 저장소
```

- **Kiosk Main Server**만 이 저장소에서 구현. VLM 서버·하드웨어 서버는 외부(클라이언트만 구현).
- 백엔드 계층 구조(의존 한 방향): `router → service → repository / integration → DTO`
  - `app/core/config.py` — 모든 설정 단일 소스(env 접두사 `KIOSK_`, `.env`)
  - `app/domain/constants.py` — 5대 불안전행동 카테고리·경광등 상태 단일 소스
  - `app/api/deps.py` — 싱글턴(integration)·서비스 와이어링
- 프론트는 `kiosk.html` + `css/`(design-system/style/integration) + `js/`(app.js 디자인 · backend.js 서버 연동).
  backend.js 가 app.js 의 더미 함수를 window 재할당으로 덮어쓴다.

### 주요 엔드포인트 맵

| Method/Path | 역할 |
|---|---|
| GET `/health`, `/docs` | 상태/문서 |
| GET `/space-name` | 공정 목록 + 불안전행동 카운트(신호등 행렬) |
| POST `/behavior/reset` | 카운트 0 리셋 |
| GET `/sensor/temp-humid?sensor_name=` · `/sensor/watch` | 온습도/심박 라이브 |
| GET `/modal/msds` · `/modal/risk` | MSDS/위험성평가(소스 더미) |
| GET `/cctv/live?cam=N` · `/cctv/live/frame` | 카메라별 RTSP→MJPEG 중계 / 단일 프레임 |
| GET `/cctv/frame` · `/cctv/stream` | Shared Dir 프레임(하드웨어 서버 기록분) |
| PUT `/cctv/{cam_id}` | DB rtsp_url/frame_dir 수정(IP 변경 무중단 반영) |
| POST `/vlm/infer` | 위험행동 분석 파이프라인(카운트·TTS·경광등) |
| POST `/vlm/prompt` | **자유 프롬프트 질의(신규 CCTV 모달 자막)** |
| POST `/vlm/stop` | 대기 TTS 폐기 |
| POST `/vlm/scheduler/start|stop|status` | 서버 측 다중 카메라 분석 스케줄러 |
| POST `/led/trigger` · `/led/off` · GET `/led/devices` | 실물 경광등 제어/진단 |
| GET/PUT `/led/thresholds` | 경광등·신호등 공용 기준치(런타임 단일화) |
| POST `/tts/demo` | TTS 단독 데모 |

## 2. DB (Shared DB · MySQL `dasol` on Jetson)

ERD 5테이블을 `SqlRepository`(PyMySQL raw SQL)로 실시간 조회/갱신. 연결 실패 시 부팅 실패(fail-fast).

| 테이블 | 내용 |
|---|---|
| `process` | 공정(process_id/name + behavior/th/hb/cctv FK). API 공정코드 = `str(process_id)` (레거시 `PRC-19` 별칭 지원) |
| `unstable_behavior` | 공정별 불안전행동 누적 카운트 5컬럼 |
| `temperature_humidity_sensor` | 온습도 **시계열(append)** — `sensor_name`(shelly_1/sonoff_1)별 최신 행 조회 |
| `heartbeat_sensor` | 심박(갤럭시워치 1대 실측) |
| `cctv_info` | 카메라별 `rtsp_url` + `frame_dir`(VLM 분석용 프레임 폴더) |

- 행동 키 ↔ 컬럼: `helmet_off→hat_removal_count`, `cone_touch→speaker_touch_count`,
  `fence_crossing→restricted_area_count`, `ladder_alone→ladder_alone_count`, `safety_vest→safety_vest_count`.
- ERD에 없는 MSDS/위험성평가/워치 작업자 명단은 `repositories/dummy_data.py` 소스 더미.
- 초기 세팅 SQL: `docs/DB_초기세팅.md` (process+unstable_behavior 연결 필수 — 없으면 분석 500).

## 3. CCTV 파이프라인 (RTSP → MJPEG, 총 2대)

브라우저는 RTSP를 직접 재생할 수 없으므로 서버가 `RTSP → JPEG → MJPEG(multipart/x-mixed-replace)` 로 중계한다.

```
[IP 카메라 N] --RTSP(TCP)--> RtspCamera(백그라운드 스레드, 최신 1프레임만 유지)
                                 ↓ /cctv/live?cam=N
                             [브라우저 <img id="cctvImage">]
```

- `RtspCamera`(`integrations/rtsp_stream.py`): lazy start, 자동 재접속(3초), `set_url()` 무중단 URL 교체,
  OpenCV(FFmpeg 내장) 디코딩. 미연결 시 placeholder JPEG.
- **다중 카메라**: `deps.rtsp_camera_for(cam_id)` 가 DB `cctv_info.rtsp_url` 기준으로 카메라별
  인스턴스를 캐시·재사용. `PUT /cctv/{cam_id}` 로 IP를 바꾸면 스트림이 재시작 없이 재접속.
- **키오스크 배치(사업장 지도 CCTV 탭, 2026-07-02 개편)**:
  - **CAM-1(좌측)** — 기존 CCTV. 모달에서 라이브 스트림 + VLM 위험행동 분석 오버레이(분석 자체는
    메인화면 "위험행동 분석" 토글이 제어). 이상 감지 시 지도 아이콘 빨간 점멸 + 미니 팝업.
  - **CAM-2(우측)** — 신규 CCTV. 모달 팝업 즉시 **`POST /vlm/prompt` 질의 루프** 시작(아래 4-2).
- Shared Dir 경로(`/cctv/frame|stream`)는 하드웨어 서버의 30fps 프레임 기록분을 읽는 별도 소스(통합 대기).

## 4. VLM 파이프라인

외부 VLM 서버(Jetson Thor, PORT 8000, Qwen2.5-VL + LLM 2단계)는 프레임 **폴더 경로**를 받아 분석한다.
서버 장애 시 무탐지 처리(거짓 경보 방지) — 파이프라인은 계속 돈다.

### 4-1. 위험행동 분석 — `POST /vlm/infer` → VLM `/analyze`

```
/vlm/infer {camera_id, process_code?, frame_dir?, labels?}
  ├─ 카메라 기준 공정·프레임폴더 자동 해석(DB cctv_info — 요청에 없을 때)
  ├─ VLM /analyze {dir_path, labels?} → {labels(탐지 키), tts_message, ...}
  ├─ action 키 → 5대 카테고리 직접 매핑(키워드 매칭은 레거시 폴백)
  ├─ 행동별 독립 쿨다운(기본 10s) — 통과분만 이후 단계 진행
  ├─ BRANCH A: 탐지 있을 때만 TTS 합성 → 스피커 fire-and-forget 재생(비블로킹)
  ├─ BRANCH B: DB 카운트 +1 → 기준치 비교 → 경광등 상태 산정 → 실물 LED 자동 점등
  └─ 통합 응답(탐지/경고문/카운트/경광등/TTS 상태)
```

- **5대 불안전행동**: 안전모 미착용(helmet_off) · 라바콘 접촉(cone_touch) · 위험 펜스 넘음(fence_crossing)
  · 사다리 단독 이용(ladder_alone) · 안전 고리 미착용(safety_vest).
- **경광등 발동 규칙**: ① 이번 사이클 탐지(쿨다운 통과)가 있을 때만 발동 — 카운트 단독 발동 금지.
  ② 다중 탐지 시 카운트 최고 항목의 단계 적용. ③ 단계: 관심(초록)<주의(노랑)<경고(빨강)<위험(순차점멸).
- **기준치 런타임 단일화**: 신호등 UI·실물 경광등이 같은 값 공유. `GET/PUT /led/thresholds` +
  JSON 파일(`light_thresholds.json`) 영속화. `.env` 값은 최초 시드일 뿐.
- **분석 트리거 2경로**:
  - 프론트 루프(`js/backend.js`): 메인화면 토글 ON → CAM-1 대상 연속 요청(응답 도착 주도).
  - **서버 스케줄러**(`services/vlm_scheduler.py`): 브라우저 없이 DB 카메라 목록을 주기 순회 —
    카메라별 공정/frame_dir 로 순차 분석(VLM 워커 1개라 동시 요청 금지). `/vlm/scheduler/*` 로 제어,
    `KIOSK_VLM_SCHEDULER_AUTOSTART` 로 부팅 자동 시작 가능.

### 4-2. 자유 프롬프트 질의 — `POST /vlm/prompt` → VLM `/prompt` (2026-07-02 신규)

```
CAM-2 모달 오픈 → 즉시 질의 루프 시작
  /vlm/prompt {camera_id, prompt(사용자 입력), path?}
    ├─ path 해석: 명시값 > DB cctv_info.frame_dir > 설정 기본값
    └─ VLM /prompt {path, prompt} → 답변 텍스트 정규화 {ok, text}
  → 프론트 자막 큐에 push → CCTV 화면 하단 반투명 자막에 타자 효과로 출력
```

- 카운트·TTS·경광등 파이프라인과 **무관한 순수 질의**.
- **자막 큐 규칙**: 한 메시지를 다 쓰면 큐의 **가장 최근 메시지만** 꺼내고 나머지는 폐기 —
  응답 속도가 타자 속도보다 빨라도 지연이 누적되지 않는다.
- 프롬프트는 모달 하단 입력 바에서 사용자가 직접 입력(매 요청 시점에 읽어 다음 질의부터 반영).

## 5. TTS (스피커 음성 안내)

```
VLM tts_message → TtsService.synthesize() → 오디오 파일 → SpeakerActuator.play_async()
                                                          (백그라운드 스레드, 즉시 응답)
```

- **엔진 2종**(`KIOSK_TTS_ENGINE`): `piper`(기본, **오프라인/폐쇄망** — 커뮤니티 한국어 KSS 모델) /
  `edge`(온라인, MS Azure 필요 — 폐쇄망 불가로 교체됨).
- 재생 세대(epoch) 기반 폐기: `POST /vlm/stop`(모달 종료·토글 OFF)이 대기/지연 TTS를 버린다(재생 중인 건 유지).
- 음성은 **kiosk-server가 실행되는 기계의 오디오 출력**으로 재생 — 시연 시 스피커 연결 위치 주의.

## 6. 경광등 (실물 LED · ST80EL-USB HID)

```
VLM 단계 산정 → LedService.trigger(level)  ┐ 같은 경로
신호등 헤더 버튼(관심/주의/경고/위험) 클릭 ┘ POST /led/trigger → HID 패킷 → 5초 점등
```

- 매핑: 관심=초록 점멸 / 주의=노랑 점멸 / 경고=빨강 점멸 / 위험=초록→노랑→빨강 순차 점멸(각 5초).
  (실물이 G/Y/R 3색이라 UI의 "주황(경고)"은 빨강으로 동작)
- 점등은 백그라운드 스레드(HTTP 즉시 응답), 전역 락으로 중복 점등 방지(409).
- 폴백: hidapi 미설치 → `simulated`(개발 PC) / 장치 열기 실패 → 503(Jetson 권한 — udev 규칙 `99-warning-light.rules` 권장).
- 제어 모듈 `warning_light_control/` 은 외부 저장소를 복사해 자체 완결.

## 7. 센서 (온습도 · 심박)

- **온습도**: 실센서 2대 — `shelly_1`(부스 A, 4분 주기) / `sonoff_1`(부스 C·하단 라이브 배지, 5초/2초 주기).
  시계열 테이블에서 `sensor_name` 별 최신 행 조회. 나머지 아이콘은 더미.
- **심박**: 갤럭시워치 1대 실측 → `WATCH-01` 에 매핑, 나머지 작업자는 더미.
  상태 산출: ≥130 위험 / ≥110 주의 / 그 외 정상.
- 프론트 폴링: 신호등 행렬 2초 · 라이브 배지 2초 · 모달은 열려 있는 동안만(닫으면 자동 정지).

## 8. 프론트 구조 (`kiosk.html` / `js` / `css`)

- 파일 분리: `kiosk.html`(마크업) / `css/design-system.css`(토큰) / `css/style.css`(본 스타일) /
  `css/integration.css`(기능 위젯 스타일) / `js/app.js`(디자인·정적 동작) / `js/backend.js`(서버 연동, app.js 덮어씀).
- 주요 화면: 신호등 행렬(5행×4단계 램프, 2초 자동 갱신) · 기준치 설정 패널 · 사업장 지도
  (온습도/CCTV/심박 탭) · CCTV 모달(CAM-1 분석 오버레이 / CAM-2 프롬프트 자막+입력 바) ·
  공정관리(MSDS 드릴다운) · 현장 특이사항(VLM/심박/온습도 이상 롤링 로그) · 법령요지 등.
- API 베이스 해석: `?api=` 오버라이드 > `file://`→localhost:8080 > 표준포트(80/443)→동일 origin > 동일 호스트:8080.

## 9. 실행 / 운영 메모

```bash
# 기동 (Windows / Jetson 공통)
.venv/Scripts/python -m uvicorn app.main:app --host 0.0.0.0 --port 8080
# 키오스크: http://localhost:8080/kiosk.html · Swagger: /docs · 상태: /health
```

- 설정은 전부 `.env`(접두사 `KIOSK_`) — DB 접속, VLM URL, RTSP 계정, 기준치 시드, TTS 엔진, LED VID/PID 등.
- **비밀번호(DB/RTSP)는 커밋 파일에 넣지 않고 로컬 `.env` 에만** 둔다.
- **git commit/push 는 사람이 직접** 한다(AI 금지 규칙).
- Jetson: LED 는 udev 규칙(또는 sudo) 필요, hidapi 는 서버 venv 에 설치해야 함.
