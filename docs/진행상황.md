## 1. 구축 범위 (무엇을 만들었나)

다이어그램의 **Kiosk Back section** 한 대만 구현했습니다. 이 서버의 역할은 세 가지입니다.

1. **Shared DB 조회** — 하드웨어 서버가 수집·기록한 데이터를 읽음 (현재는 mock).
2. **Shared Dir 프레임 읽기** — 하드웨어 서버가 기록하는 30fps 프레임을 키오스크 화면용으로 제공.
3. **VLM 서버 `/infer` 호출 + 후처리** — TTS(스피커) + DB 카운팅 + 경광등 제어 신호 생성.

### 구현하지 **않은** 것 (외부 서버이므로)

- ❌ **Hardware Server (PORT 8081)** — `002.png` 참고용. RTSP/MQTT/센서/워치 등.
- ❌ **VLM Server (PORT 8000)** — Jetson Thor의 Qwen2.5 VLM/LLM. **클라이언트만** 구현.
- ❌ **실제 DB 스키마** — 아직 설계 전이므로, 인터페이스 뒤의 mock(JSON/in-memory)으로 대체.

## 2. 아키텍처 (계층 구조)

의존 방향은 한 방향입니다.

```
router → 요청 검증(Pydantic) → service → repository / integration → 응답 DTO
```

- **router** : 비즈니스 로직 없음. 입력 검증과 응답만.
- **service** : 비즈니스 로직 (VLM 파이프라인 오케스트레이션 포함).
- **repository** : 데이터 접근(Shared DB seam). 현재 mock 1종.
- **integration** : 외부 I/O (VLM 클라이언트, TTS, Shared Dir, 액추에이터). 전부 stub 가능.
- **schemas** : 도메인별 Pydantic DTO.
- **domain** : 4대 불안전행동 카테고리, 경광등 상태 등 상수/enum.

```
app/
  main.py                 # 앱 팩토리, CORS, 라우터 등록, lifespan, /health
  core/config.py          # 모든 설정을 env/.env 한 곳에서 로드
  core/logging.py
  domain/constants.py     # 4대 불안전행동 카테고리, 경광등 상태
  schemas/                # space / sensor / modal / vlm / common DTO
  repositories/           # base 인터페이스 + mock 구현 + factory(DB 교체 지점)
  integrations/           # vlm_client / tts / shared_dir / actuators
  services/               # space / sensor / modal / cctv / vlm 서비스
  api/routers/            # space / sensor / modal / cctv / vlm / health
mock_data/                # Shared DB 행을 모사한 JSON 픽스처
docs/진행상황.md          # (이 문서)
```

## 4. VLM 추론 파이프라인 (001.png 우측 흐름)

`POST /vlm/infer` 호출 시:

1. **VLM 서버 호출** — `vlm_client` 가 외부 VLM `/infer`(기본 `http://localhost:8000`)에 POST.
   응답은 `{ "탐지": "...", "위험 경고 텍스트": "..." }` 형태. 서버 오프라인/실패 시 **내장 mock** 으로 폴백.
2. **Branch A — TTS 텍스트 추출**: `위험 경고 텍스트` → Edge TTS 음성 변환 → **스피커**(액추에이터, stub).
3. **Branch B — DB 텍스트 추출 + 경광등**:
   - `탐지` 값을 키워드로 파싱 → 4대 불안전행동 카테고리로 분류(`파싱 & DB 반영`).
   - 해당 카테고리 카운트 **+1** (mock DB).
   - 반영 후 카운트 **조회**.
   - 카운트 → **경광등 제어 신호 생성**(임계값 기반). 예: count 3 → `노란색 볼 깜빡임`.
   - 신호를 **경광등**(액추에이터, stub)으로 전송.
4. **응답 결합**: 탐지/경고문/카테고리+카운트/경광등 신호/TTS 상태를 한 JSON으로 반환.

### 경광등 임계값 (설정값, 튜닝 가능) — 섹션 12에서 3/6/9/12로 변경됨
| 누적 카운트 | 상태 | 단계 | 한글 제어 신호 |
|---|---|---|---|
| 0 ~ 2 | off | - | 소등 |
| 3 ~ 5 (`KIOSK_LIGHT_INTEREST_THRESHOLD=3`) | green | 관심 | 녹색 점등 |
| 6 ~ 8 (`KIOSK_LIGHT_CAUTION_THRESHOLD=6`) | yellow_blink | 주의 | 노란색 깜빡임 |
| 9 ~ 11 (`KIOSK_LIGHT_WARNING_THRESHOLD=9`) | red_blink | 경고 | 빨간색 깜빡임 |
| 12+ (`KIOSK_LIGHT_DANGER_THRESHOLD=12`) | sequence | 위험 | 순차 점멸 |

> 누적 카운트는 **4대 행동의 최대 누적값(조회 결과)** 기준이며 초기화 전까지 유지된다.

### 4대 불안전행동 카테고리 (프론트 슬라이드와 동일)
| id | 이름 | 기본 등급 | 파싱 키워드(예) |
|---|---|---|---|
| `helmet_off` | 모자(안전모) 벗는 행동 | 위험 | 안전모, 헬멧, helmet |
| `touch_equipment` | 스피커(설비) 만지는 행동 | 주의 | 설비, 스피커, 만지 |
| `unauthorized_crossing` | 위험지역 무단횡단 행동 | 정상 | 무단횡단, 위험지역, 출입 |
| `ladder_alone` | 사다리 혼자 올라가는 행동 | 정상 | 사다리, 단독, ladder |

## 5. 무엇이 mock 이고, 실제 연동은 어디에 끼우나

| 대상 | 현재 (mock) | 실제 교체 지점 |
|---|---|---|
| **Shared DB** | ✅ **MySQL 연동 완료** (`repositories/sql_repository.py`, PyMySQL). `KIOSK_REPOSITORY=mysql` 로 전환, 실패 시 mock 폴백 | 쿼리/매핑은 `sql_repository.py`, 연결설정은 `core/config.py` `KIOSK_DB_*`. ERD 외 데이터는 `dummy_data.py` |
| **VLM 서버** | ✅ **실연동 완료** (`vlm_client.py` → 실제 Jetson `/analyze`). 오프라인/실패 시 mock 폴백 | `KIOSK_VLM_BASE_URL`/`KIOSK_VLM_FRAME_DIR` 설정. 매핑은 `domain/constants.py::VLM_ACTION_KEY_MAP` (섹션 11) |
| **TTS 재생** | ✅ **실재생** (Edge TTS 합성 + `playsound`). `play_async()` 백그라운드 스레드 | `integrations/actuators.py::SpeakerActuator` |
| **경광등(VLM 파이프라인)** | `WarningLightActuator` 로그 stub (제어 신호 생성·로깅) | 실물 LED는 `led_service.py`에 별도 구현됨 → VLM 자동 연동은 TODO |
| **Shared Dir** | 프레임 없으면 placeholder JPEG | `KIOSK_SHARED_DIR` 를 실제 프레임 디렉터리로 |

모든 설정은 `app/core/config.py`(env 접두사 `KIOSK_`)에 집중. `.env.example` 참고.

### 8-2. 백엔드 변경사항

#### 새 엔드포인트: `POST /behavior/reset`

```http
POST /behavior/reset?process_code=PRC-19
Content-Type: application/json

Response 200:
{ "reset": true, "process_code": "PRC-19" }
```

- **동작**: 지정한 공정의 4대 불안전행동 카운트를 모두 0으로 초기화.
  경광등 상태는 count=0이므로 다음 VLM 호출 시 자동으로 `green(녹색 점등)` 신호 발생.

VLM 파이프라인에서 경광등 단계 산출 후 `led_service.trigger(level)` 를 자동 호출.

### 12-3. [분석] 버튼 TTS 통합 (프론트)

> **TTS 재생 위치(시연 유의)**: 음성은 kiosk-server가 실행되는 PC의 오디오 출력으로


> 참고: 테스트로 `/vlm/infer` 를 30회 자동 호출하면 TTS도 30회 재생되지만, 이는
> 임계값 전환 확인용 루프일 뿐이며 **실제는 [분석] 1클릭 = 1회 재생**이다.

## 13. 프론트엔드 라이브 갱신 — 센서 모달 폴링 + CCTV VLM 연속 분석 (2026-06-25)

### 배경

기존 프론트는 모달/분석이 **클릭 시 1회**만 값을 가져왔다. 현장 모니터링 특성상
모달을 열어 둔 동안 값이 계속 갱신되는 편이 자연스럽다는 요구에 따라,
두 영역을 "열려 있는 동안 반복 요청 → 닫으면 중단" 구조로 전환했다.
백엔드 API 변경은 없고 **`js/backend.js`** 만 수정.

### 13-1. 라이브 센서 모달 주기 갱신 (온습도 / 심박)

| 항목 | 이전 | 이후 |
|---|---|---|
| 값 갱신 | 모달 열 때 1회 fetch | **열려 있는 동안 3초 주기 재요청** |
| 종료 | — | 모달 닫으면 폴링 정지 |

- **모달별 폴링 매니저** `startModalPoll(overlayId, fn)` / `stopModalPoll(overlayId)` 추가.
  같은 모달 재오픈 시 기존 인터벌을 먼저 정리해 **중복 인터벌 누적 방지**.
- 닫기: `closeModal` 을 래핑해 닫기 버튼 클릭 시 즉시 정지. 배경 클릭 종료는
  인터벌 내부의 `.open` 체크가 다음 틱에 자동 정리(닫힌 뒤 추가 요청 없음 — fetch 전 상태 확인).
- 대상 함수의 "값 가져오기 + DOM 갱신" 로직을 내부 `update()` 로 추출해 최초 1회 + 주기 호출에 공용 사용:
  `openEnvDetail`(온습도), `openHeartRate`(심박 그룹), `openWatchWorker`(심박 개인).
- 라이브 센서(TH-03 / WATCH-03)는 매 주기 `/sensor/temp-humid`·`/sensor/watch` 재호출,
  그 외 더미 센서도 매 주기 값이 변동.

### 13-2. CCTV VLM 연속 분석 루프

| 항목 | 이전 | 이후 |
|---|---|---|
| 분석 트리거 | `[분석]` 버튼 1클릭 = `/vlm/infer` 1회 | **모달 열림과 동시에 분석 시작** |
| 반복 | 없음 | **응답이 오면 즉시 다음 요청** (네트워크 왕복이 자연 스로틀) |
| 종료 | — | 모달 닫을 때(X · 배경 클릭) 중단 |
| `[분석]` 버튼 | 1회성 요청 | **일시정지 / 재개 토글** |
| 오류 | 토스트 + 종료 | **~1.5초 백오프 후 재시도**(오버레이에 오류 텍스트만, 토스트 스팸 방지) |

- **루프 엔진** `startVlmLoop(opts)` / `stopVlmLoop()` + 상태 `vlmLoop = { token, paused }`.
  - `token` 세대값으로 **이전 루프·in-flight 응답을 무효화** → 닫은 뒤 늦게 온 응답이 화면을 덮어쓰지 않음.
  - 매 반복마다 `cctvModalOpen()`·`token` 일치 확인(안전망).
- `runVlmAnalysisOnce(token)` : 기존 fetch+렌더 로직 추출. 응답 도착 시 token 불일치/모달 닫힘이면 렌더 생략.
- **카메라 전환**(`switchCam`): `startVlmLoop({ keepPaused:true })` 로 새 카메라에 즉시 재타게팅하되 일시정지 상태는 유지.
- 변경 함수: `openCCTV`·`openCCTVFor`(시작), `closeCCTV`(중단+버튼 복원), `switchCam`(재타게팅),
  `analyzeCurrentCam`(토글로 재정의). 신규: `startVlmLoop`/`stopVlmLoop`/`runVlmAnalysisOnce`/`renderVlmResult`/`updateAnalyzeBtn`/`resetAnalyzeBtn`.
- HTML 미변경(버튼 `onclick="analyzeCurrentCam()"` 그대로 재사용).

### 13-3. 검증

- `node --check js/backend.js` 통과(문법).
- 모달 동작 검증은 백엔드(8080) 기동 상태에서 온습도/심박 모달·CCTV 모달을 열어 확인.
